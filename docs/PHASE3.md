# Phase 3 — Editing depth

See [PLAN.md](PLAN.md#phase-3--editing-depth) for the whole phase and [USABILITY.md](USABILITY.md) for the decisions behind it. Phase 3 adds darktable's editing tools behind Lightroom-style controls. It starts with the groundwork they need: process versions, so that rendering changes never alter existing edits, and the Develop tool stack that the new tools join, with Crop as its first group.

## Part 1: Process versions, the tool stack, and Crop

**What it does.** Three things. Every edit now records which version of LightBench's rendering it uses (its **process version**), so later rendering changes never silently change an existing edit. Develop's right panel is now **one scrolling stack of tool groups** in workflow order with a **jump bar**. Its new first group is **Crop**: crop, straighten, rotate 90° and flip, on the photo and in the panel, Lightroom-style.

Owner's choices (2026-10-12):
1. **Process versions first.** Existing edits are version 1 (today's rendering); new edits get the current version; rendering code can branch on the version; the version is shown unobtrusively and an older edit offers **Update to current process**, which can be compared and undone through the history. Today there is one rendering, so this is the mechanism and its tests.
2. **The tool stack**, already decided after round 2: one scrolling stack, Crop & Lens first, then Basic; collapsible groups; a jump bar with icons and one-word labels (labels hide when narrow, the name shows on hover). Only groups with content exist (Crop, Basic); Curve, Colour, Detail and Effects slot in later. The on/off **eye** per group (an idea from LightCraft; LightBench's choice to include it) shows the photo without that group.
3. **Crop, Lightroom-style:** **R** opens it on the photo (an action in the shortcut registry, so it can be changed); drag corners or edges to resize, inside to move, outside to turn; the crop box stays level and the photo turns under it (Lightroom's way; LightCraft turns the box instead). Aspects Original, 1:1, 4:5, 5:7, 2:3, 16:9 and Custom, with a lock; **X** swaps portrait and landscape; **O** cycles thirds, grid, golden ratio and diagonals while cropping; **Enter** applies, **Esc** cancels; a Reset.
4. **Straighten:** an Angle slider (−45…+45°, 0.01° steps; the crop shrinks to stay inside the photo) and a level line drawn along the horizon or a wall (the **Level** button, or **Ctrl-drag** while cropping, as in LightCraft (and, from general knowledge, Lightroom; not checked here)). **Rotate left/right** (Ctrl+[ / Ctrl+]) and **flip** horizontal/vertical. Auto straighten comes later with Upright.

### Process versions

| Behaviour | Detail | Source |
|---|---|---|
| What is stored | `process` in the develop settings (`engine/develop/settings.ts`), saved in the catalog, the history and the `lightbench:Develop` sidecar field. It is separate from the settings' existing `version: 1`, which numbers the JSON layout (the schema) and stays as it was. | Owner's decision; design LightBench's |
| Old and new edits | A saved edit without `process` (everything saved before 0.3.0) reads as version 1. New edits, unedited photos and **Reset all** get the current version. A malformed value reads as 1. | Owner's decision |
| What a version covers | Everything that turns the same settings into different pixels: the RAW stage (white level choice, highlight reconstruction, demosaic), colour (camera matrix, white balance maths), the slider mappings (Exposure, the Contrast → sigmoid mapping, the tone-equalizer bands behind Highlights/Shadows/Whites/Blacks, Vibrance/Saturation), the display transform, and the geometry stage (crop rounding and the warp kernel). A change that would alter a saved edit's pixels needs a new version; fixes for broken output and new tools that are off by default don't. Written down in `engine/develop/process.ts`. | LightBench |
| Branching on it | Each version has its own parameter set (`processParams(version)`): today the tone range, the tone-equalizer band weights and the contrast spread, moved out of fixed constants. `displayUniforms` and `toneBands` read them from the photo's version. A future version adds an entry; version 1's entry never changes. | LightBench |
| Shown | At the foot of the tool stack: “Process version 1 (current)”. An older edit also shows, above the groups, “This photo was edited with process version N” and **Update to current process**, which records one history step “Update to process M”: the step before it shows the old rendering, Ctrl+Z goes back. An edit from a newer LightBench says so and is shown with the newest version this build knows, never rewritten. | Lightroom's process version and its update prompt (from general knowledge of Lightroom; not checked in Lightroom here) |
| Copy/paste | **Process version** is an item of the paste checklist's Advanced group (unticked by default, like the rest of that group). | Lightroom's Copy Settings lists Process Version (not checked here) |
| Testing an update | Only one rendering exists, so no real edit is older than current. On the development server, `?simulateProcess=2` adds a copy of version 1 as version 2 so the offer can be tried; production builds leave it out (`import.meta.env.DEV`). | Test scaffolding |

### Crop, straighten, rotate and flip

| Behaviour | Detail | Source |
|---|---|---|
| Open | **R**, the **Crop** button in the toolbar, or **Crop…** in the Crop group. The whole photo is shown turned by the straighten angle, with the crop box over it, the area outside dimmed and a 28 px margin for the handles. Zoom is fit while cropping. | Lightroom (R = Crop Overlay); key in the registry |
| Resize and move | Drag a corner or an edge (the opposite corner or edge stays), or drag inside to move. The box stops at the photo's edge and slides along it. With the aspect locked, corners and edges keep the shape (an edge grows about its middle). Smallest crop: 2 % of the short side. | LightCraft `crop_drag.rs`, ported |
| Turn | Drag outside the box: the photo turns under the level box (a grid and the angle show while dragging). The crop is computed from where the drag started, so turning back within one drag gives the crop back. | Lightroom (box level, photo turns); LightCraft turns the box instead, not copied |
| Angle slider | −45…+45° in 0.01° steps (arrow keys 0.45°, Shift+arrows 4.5°; double-click or Home resets). Moves continue from the crop before the slider started moving. | Owner's decision; step sizes from the slider keys (Part 12) |
| Crop stays inside | When the angle changes, a crop that still fits is kept. Otherwise it shrinks about its own centre, keeping its aspect, until it fits; if its centre is outside the turned photo, it becomes the largest crop of its aspect, centred. | LightCraft `with_angle` (largest centred crop); shrinking about the crop's own centre is LightBench's change, so the box doesn't jump |
| Level line | **Level**, or **Ctrl-drag** (⌘ on a Mac) while cropping: draw along something that should be level or upright. Lines closer to horizontal become horizontal, closer to vertical become upright; the photo turns by the line's tilt (if the result stays within ±45°). | Lightroom's Straighten tool; LightCraft also uses ⌘/Ctrl-drag |
| Aspect | Original, 1:1, 4:5, 5:7, 2:3, 16:9, Custom (width : height). Picking one locks it and makes the largest crop of that shape at the current angle, centred on the crop. The menu shows ratios in the crop's shape (3 : 2 for a landscape crop, 2 : 3 for a portrait one). The lock starts on, at Original. Locking a free crop keeps its shape (named if it matches a menu entry, else Custom). | Owner's list; default locked to Original is LightBench's choice (Lightroom's default not checked) |
| Swap | **X** (or the button): portrait ⇄ landscape about the crop's centre, shrunk to fit if needed. | Lightroom's X (not checked here) |
| Overlays | Thirds, Grid (8 × 8), Golden ratio (lines at 0.382 and 0.618), Diagonals (45° from each corner). **O** cycles them while cropping; outside the crop tool O still shows clipping, because the shortcut registry gives cropping its own context. The choice is remembered in this browser. | Owner's list; Lightroom's O cycles crop overlays (not checked here) |
| Apply, cancel, undo | **Enter**, R again, or **Done** apply the crop as one history step (“Crop”, or “Straighten” when only the angle changed). **Esc** or **Cancel** drop it. While cropping, Ctrl+Z / Ctrl+Y undo and redo crop changes. Leaving the photo (filmstrip, another module) applies it (not tested end to end; Lightroom's behaviour here not checked). | Owner's decision |
| Reset | Puts crop, straighten, rotate and flip back (one history step outside the crop tool). | Owner's decision |
| Rotate and flip | **Ctrl+[** / **Ctrl+]** turn left/right (in Develop, also while cropping); Flip horizontal/vertical in the Crop group and in command search (no key by default). The crop turns and mirrors with the photo, so it stays on the same content; a flip mirrors the straighten angle too. Outside the crop tool each is a history step. These are part of the edit (on top of the camera's orientation), unlike Lightroom, where rotating changes the photo's orientation metadata. | Owner's keys (Lightroom's Ctrl+[ / Ctrl+]); storing them in the edit is LightBench's choice |
| Size | The crop's size in pixels (what Export writes at 100 %) is shown in the group. | LightBench |

### The geometry stage and where the crop is used

| Behaviour | Detail | Source |
|---|---|---|
| One resample | Lens correction → rotate and perspective (straighten; later Upright) → flip (camera orientation + the user's turns and flips) → crop, darktable's pixelpipe order, are combined into one projective map from output pixels to the sensor (`engine/develop/geometry.ts`, `resolveGeometry`). Lens correction and perspective are identity for now and join the same map later, so a photo is resampled once whatever tools are used. | darktable `src/common/iop_order.c` (v5.0 order: lens 13, ashift 15, flip 16, crop 24.5); combining them is LightBench's choice (darktable's modules each resample) |
| Interpolation | With a straighten angle, the scene is warped once with bicubic interpolation (Catmull-Rom, a = −0.5) into a cached texture with its own mip chain (`engine/gpu/warp.wgsl`). Without an angle the map is whole-pixel (orientation, turns, flips, crop) and the scene is read directly: nothing is resampled. | darktable's default warp interpolator is bicubic: `plugins/lighttable/export/pixel_interpolator_warp` defaults to `bicubic` (`data/darktableconfig.xml.in`) and `DT_INTERPOLATION_DEFAULT_WARP = DT_INTERPOLATION_BICUBIC` (`src/common/interpolation.h`); its `_maketaps_bicubic` is the a = −0.5 cubic (`src/common/interpolation.c`) |
| Cache | The last warped scene is kept per scene and map: exposure, tone and colour sliders, Auto, the histogram, thumbnails and exports reuse it. Before/after and the eyes (which show no geometry) don't evict it. A new RAW stage (white balance, highlight reconstruction, demosaic) or another photo drops it. | LightCraft review (“cache the warped result”) |
| Crop coordinates | Normalised (0…1) in the straightened frame: the photo after every geometry correction except the crop, in its final orientation. So crops (and later masks) stay on the same content when lens or Upright settings change. | Owner's requirement; LightCraft's model |
| Whole pixels | The crop is rounded inwards to whole pixels, so a turned crop never reads outside the photo. A locked aspect gets the whole-pixel size nearest to it (a 1:1 crop is exactly square). A crop found outside the turned photo (e.g. pasted where the photo's size wasn't known) is pulled inside before rendering. | LightBench |
| Everywhere | Develop's view, the histogram and clipping, **Auto** (it measures the cropped frame), Export (`renderOutput`: the crop at 100 %, then resized), thumbnails (`renderThumbnail`), the culling/Compare/Survey 100 % renders (`FullRenderer`), the background developer (Paste, Sync, Auto Sync, presets, develop new photos) and virtual copies all render through the same map, because the geometry travels in `displayUniforms`. The white balance picker and the sensor-clipping overlay map through it too. | Owner's requirement |
| Old edits | An edit without geometry renders exactly as before: the map is built in uv units from 0, 1 and −1 entries and equals the old orientation map (unit test), and the full-size export of a 0.2.0 edit is bit-identical (below). | Owner's requirement |

### Copy, paste and presets

| Behaviour | Detail | Source |
|---|---|---|
| Checklist | A new **Crop** group in the Copy/Sync/Paste/New preset checklist: **Rotate & flip**, **Straighten angle**, **Crop** (rectangle, aspect and lock). Unticked by default, like the Advanced group. | Lightroom doesn't copy the crop unless it is ticked, as the owner described it; not checked in Lightroom here, so also LightBench's choice |
| Order | Pasted in that order: the orientation first (the crop is relative to it, and turning moves the crop with the photo), then the angle (the target's crop shrinks to fit), then the rectangle. | LightBench |
| Other shapes | A crop with a locked aspect keeps that aspect on a photo of other proportions (the largest rectangle of the ratio inside the pasted one, about its centre); a free crop is copied proportionally. The crop is then kept inside the target photo at its angle. | LightBench's choice |
| Presets and Amount | Presets can hold the crop items. The Amount slider treats geometry like the other switches: it follows the preset whenever the amount is above 0. | As Part 8 |
| Sidecars | The geometry is part of the settings in `lightbench:Develop`. Lightroom's `crs:Crop*` fields are not written yet (follow-up). | Owner's decision |

**Limitations:**
- The fitted views of the Library loupe and culling still show the camera's embedded preview, which ignores all edits (as before), so a crop appears there only at 100 % and in thumbnails.
- While straightening outside the crop tool (the Angle slider), every slider step warps the photo again at full resolution: expected to be quick on a real GPU (not measured on the owner's GPU yet) and visibly slower on the software GPU used for testing (not measured). Inside the crop tool the photo is drawn directly and nothing is warped until the crop is applied.
- The warped copy is a second full-resolution texture (8 bytes per pixel: about 190 MB for a 24 MP crop, plus a third more for its mips) while a straightened photo is open.
- At the very corners of a maximal straightened crop, the bicubic taps reach up to two pixels past the photo's edge and repeat the edge pixels (darktable's interpolation does the same).
- Lightroom's `crs:Crop*` sidecar fields aren't written or read, so Lightroom and darktable don't see LightBench's crop. Auto straighten comes with Upright.
- The Lightroom behaviours quoted (R, X, O in the crop tool, Ctrl-drag to straighten, the copy default, process version updates) are from general knowledge and the owner's description, not checked in Lightroom or against Adobe's pages here.
- Only one rendering exists, so the update offer was tested with the development server's simulated version 2.
